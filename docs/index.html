Documentation

A clearer path from
request to review.

ADE is a local toolkit around Claude Code. Your intent, specification and implementation plan live beside your code. Humans own acceptance and release decisions.

The toolkit source is currently private. Request access from Behzad. This guide and the example files are public; no account is needed to read them. An MIT core release is planned.

Preview before you install.

Requirements: Python 3.10+, Bash, Git and Claude Code. ADE is tested on macOS and Linux. Windows users can use WSL; native Windows is not currently tested. Your project must already be a Git repository.

After receiving a reviewed toolkit checkout or archive, run the script from its directory: 

python3 /path/to/ade/ade init \
  --project /path/to/project --dry-run

python3 /path/to/ade/ade init \
  --project /path/to/project

python3 /path/to/ade/ade doctor \
  --project /path/to/project

Quote paths that contain spaces. No Python packages or network requests are needed. ADE does not include a Claude subscription. Follow Anthropic’s setup instructions for Claude Code.

What changes in your repository?

  • ADE.md provides the workflow instructions. An import is appended to CLAUDE.md.
  • Two local hook entries are merged into .claude/settings.json. Existing permissions and hooks remain.
  • Intent, spec, plan and finding templates; six lifecycle plays; a review policy; example control bands; and a simulated promote script are added.
  • Original settings and context are backed up with an .ade-backup suffix. Existing custom content is preserved; conflicting runtime files stop installation.

Review the installation diff, then restart Claude Code to load the hooks. The doctor command checks registration and file integrity; verify the hooks appear in Claude Code before relying on them.

Start one small change.

python3 /path/to/ade/ade new password-reset \
  --title "Add password reset" \
  --project /path/to/project

python3 /path/to/ade/ade status \
  --project /path/to/project

This creates three draft artifacts and selects the active intent. It does not accept the work. Have Claude propose the problem, acceptance criteria and plan in plan mode. A human edits and reviews the draft files in their editor, then sets the plan’s frontmatter to status: accepted when ready.

Keep acceptance recorded in the pull request. The hook checks supported edits against that local plan. Normal Claude tool permissions still apply. Do not use shell writes to bypass draft checks.

Inspect a complete example.

A password-reset feature shows how the files connect. These are illustrative draft artifacts, not a bundled authentication implementation. The application code is yours to build.

Download all three files ↓

intent.md: the user problem

A user who forgets their password needs support to regain access. Let them request a reset email without revealing whether an address has an account. Keep the existing authentication provider; never log reset tokens.

Success means expired and reused links cannot change a password.

spec.md: observable behavior
  • Known and unknown emails receive the same public response.
  • Tokens expire after 30 minutes and can be used once.
  • Successful reset invalidates sessions according to the provider’s supported mechanism.
  • Expired, malformed and reused tokens produce an actionable error.
  • Rate limits apply and tokens never appear in logs.
plan.md: the implementation and checks

Use the existing authentication provider. Add request and confirmation views and connect the existing email template. Keep credentials server-side.

Test response parity, expiry, one-time use, rate limits and session invalidation. Exercise success and failure in the browser. A human reviews capabilities and evidence before release through a protected environment.

Understand the limits.

ADE is a workflow aid. Local files and hooks are editable. They do not authenticate the person named in a plan or attestation, and they are not a security sandbox or compliance certification.

  • The plan hook covers supported Claude edit tools. Direct editor changes, shell writes, disabled hooks and other agent harnesses are outside it.
  • Canonicalized file paths outside the project are denied. In-project docs, findings, README and designated templates are allowlisted; other edits need an accepted plan.
  • The Bash hook recognizes a limited set of promote patterns. The bundled promote.sh is a simulation with no deployment side effects.
  • Use Git-host review rules and protected deployment environments for real authorization. Keep production credentials outside agent-controlled scripts.
  • ADE itself makes no network requests. Claude Code, your model provider and your Git host have their own data handling policies.

Report vulnerabilities privately to behzad@airoweb.com. Do not include live credentials.

When a check stops you.

“Missing plan” or “plan must be accepted”

Run ade status. Confirm the active intent matches the change and that a human has reviewed the plan. Do not make the agent approve its own work.

Existing runtime or backup conflict

Back up and compare the existing file with the toolkit version. Reconcile manually and rerun the preview. There is no force-overwrite option.

Missing Python or Claude Code

Install Python 3.10+ for the checks. Claude Code is required to execute the hooks during agent work. Restart Claude after installation.

Remove ADE

Review the installation diff. Remove only ADE’s two hook entries and the @ADE.md import, then delete unmodified ADE files. Preserve custom files and your artifact history. Restore a backup only if it still represents the settings you want.
